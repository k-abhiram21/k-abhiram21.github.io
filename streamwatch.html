DATABASE OBSERVABILITY / FULL-STACK PROJECT

Unstructured data.
A clearer view.

StreamWatch is a monitoring workspace for MongoDB-backed applications. It brings database exploration, application metrics, and dashboard visualizations together so the system’s state is easier to understand.

The question

How do we monitor an unstructured database?

The stack

React · FastAPI · MongoDB · Prometheus · Grafana

02 THE MAIN PROBLEM

Flexible data.
Clearer monitoring.

MongoDB gives an application room to work with document data. But understanding the running system still takes a deliberate monitoring layer: what is the application doing, how are requests behaving, and how can someone explore the data?

That was the main question behind StreamWatch. I worked across the application and monitoring stack to make that activity visible in a usable workspace.

03 CONNECTING THE STACK

Two paths.
One workspace.

Application data moves through FastAPI and MongoDB. Telemetry travels through Prometheus and Grafana.

04 ONE INTEGRATION DECISION

Give a metric
some context.

One requirement was to show query activity alongside monitoring data. The usual numeric metrics didn’t carry the context we wanted to display.

I worked on custom application instrumentation to attach query context to a metric’s labels. That made a specific piece of application activity available to the visualization layer.

It was one part of the larger observability problem. The broader work connected database operations, the API, instrumentation, dashboards, and a frontend where those pieces could be explored together.

A closer look at the integration ↓

Keep application data and telemetry distinct.

React talks to the FastAPI application, which connects to MongoDB. The AI-assisted path uses Gemini to turn a natural-language question into a MongoDB query. Monitoring is a separate path: the backend exposes numeric instrumentation at /metrics, Prometheus collects it, and Grafana turns it into panels.

Instrument the activity that matters.

The backend defines client query traffic with user, client, and query-type labels, alongside a packet-size histogram. For AI query activity, a custom gauge carries the question, generated MongoDB query, result, and status in its labels. That was the bridge for showing query context beside the numeric signals; Prometheus remains the metrics collector.

Bring the view back into the workspace.

MetricFrame.jsx builds Grafana panel URLs from the dashboard, panel ID, and active theme. Vitals.jsx brings together panels for client traffic, packet-size distribution, system metrics, and query activity. The integration work spans both ends: exposing application context in a form the monitoring stack can collect, and configuring a frontend view that makes those signals accessible.
