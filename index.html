Why the obvious choice can fail.

A higher score or a more specialised component is only useful if it improves the result of the task. I try to make that comparison explicit before adding complexity.

How I frame the question ↗

What I look for in a failure.

The first useful question is often whether the code did what I intended. Once that is clear, I can decide whether to fix the implementation or revisit the idea.

Lessons from debugging ↗

Checking the experiment itself.

A result depends on the machinery that measures it. I check the inputs, the comparison, and the scoring code before treating a number as evidence.
