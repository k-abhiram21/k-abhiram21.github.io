Relevance is a starting point.

A specialist understanding the topic is only part of the question. My routing work asks whether its contribution is useful for the task. That distinction changes where I put my attention: I look at behaviour, investigate the gap between intention and outcome, and work on ways to make the decision easier to understand.

How I frame the question ↗

Complexity needs to earn its place.

Adding another component creates work as well as possibilities. I think about what it contributes, what it takes to use, and how it fits into the system around it. That keeps the engineering connected to the original problem, and gives debugging a purpose beyond simply making a larger pipeline run.

Lessons from debugging ↗

An experiment should answer the question.

I work on the code that evaluates an idea, as well as the idea’s implementation. Clear comparisons and inspectable behaviour help me understand what a result means. Tightening that engineering is part of the research: it makes the next question more precise and the next iteration easier to reason about.
